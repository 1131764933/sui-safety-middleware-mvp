# Security Assumptions（安全假设与边界）

## 1. 当前安全模型（MVP）

- 规则预审：基于白名单与额度阈值（allow/review/block）
- 人工闸门：`review` 必须先确认
- 审计记录：执行结果写入审计结构
- AI 增强：仅解释和摘要，不参与最终放行

## 2. 明确不覆盖（MVP 范围外）

- 多签与硬件钱包深度集成
- 跨链交易安全
- 复杂机器学习风控模型
- 生产级密钥托管与HSM
- 大规模并发压测与性能优化

## 3. 关键风险与约束

- API 接口仍是最小实现，需后续增加鉴权
- 审计存储目前为最小可演示逻辑，需扩展为生产级持久化
- 前端为最小闭环流程，UI 与异常态提示仍需增强
- 网络异常时，策略优先阻断，避免误执行

## 4. 后续加固建议

- 接入地址信誉与链上行为信号（多源风控）
- 增加速率限制、签名会话过期、重复交易防护
- 将关键审计信息固定为链上对象 + 长期存储
- 对执行器与合约增加更细粒度测试（不变量/Fuzz）
